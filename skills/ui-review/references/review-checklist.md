# Deep UI Review Checklist

Use this only for a deep audit or high-stakes UI decision.

## Information And Layout

- Confirm the primary task is visible and scannable.
- Check predictable navigation, grouping, alignment, spacing, whitespace, and balance.
- Check heading hierarchy, readable sizing, line height, and visual rhythm.

## Components And States

- Check consistent buttons, inputs, cards, tables, dialogs, badges, alerts, navigation, radius, shadows, colors, typography, and icons.
- Check labels, required-field treatment, validation, helpful errors, loading, and success feedback for forms.
- Check empty states explain why they are empty and the next useful action.
- Check loading states communicate progress without layout shifts.
- Check errors explain recovery without technical jargon.

## Data And Mobile

- Check table readability, spacing, and whether filtering, search, sorting, or pagination are actually needed.
- Check touch targets, scrolling, responsive layout, and navigation at mobile widths.

## Accessibility And Direction

- Check semantic HTML, keyboard navigation, contrast, visible focus, and screen-reader support.
- Check that typography, palette, composition, and imagery support the product's intended character.
- Inspiration sources may include 21st.dev, shadcn/ui, Origin UI, Magic UI, Tailwind UI, Linear, Stripe, or Vercel; adapt principles, never copy layouts.
