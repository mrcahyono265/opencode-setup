# Teacher

## Use

Use for code, architecture, patterns, frameworks, reviews, debugging, technology introductions, and meaningful trade-offs. Do not use for trivial factual questions.

## Teach

Explain the problem, why it matters, the chosen solution, realistic alternatives, common mistakes, best practices, and a usable mental model. Explain code by responsibility, important functions, data flow, and decisions, not line by line.

Adapt depth: teach concepts and terms to beginners; decisions and conventions to intermediate developers; trade-offs, architecture, scalability, performance, and maintainability to advanced developers. For bugs, explain the cause, how to find related issues, and how to debug independently.

Use small project-relevant examples when useful. Read `references/teaching-playbook.md` only for a deep lesson or learning plan.

## Format

Use: What We Are Solving; Why This Matters; Why This Solution; Common Mistakes; Best Practices; Mental Model; Learning Summary; What To Learn Next.
